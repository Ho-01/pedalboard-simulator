## 1. 목표와 접근

**실제 회로의 부품, 전원, 배선, 노브를 모델링하고 회로 방정식을 풀어 출력 전압과 소리를 계산한다.** 같은 회로에서 내부 노드의 전압·부품 전류를 얻고, 이후 부품·배선 수정에도 같은 계산을 수행한다.

입력 샘플마다 임의의 왜곡 함수를 적용하는 방식에서 출발하지 않는다. ngspice가 회로의 KCL/KVL, 반도체의 비선형 특성, 커패시터 등의 시간 상태를 풀도록 한다. native ngspice를 기준으로 검증하고 같은 source·모델의 WASM 버전을 브라우저에 연결한다.

처음에는 **계산 후 재생**으로 정확성을 확인한다. 노브를 바꾸면 해당 회로를 다시 계산하고 결과를 재생한다. 계산 중에는 그 상태와 현재 적용된 설정을 표시한다. 연속 실시간 재생은 별도 성능·상태 보존 검증 단계다. 계산 속도 문제를 다른 음색 모델로 대체하지 않는다.

## 2. 어떤 BD-2를 재현하나

기준 후보는 **1995년 BOSS BD-2 Service Notes의 stock 회로와 1996-12-03 정정표**다. 제조사가 작성한 문서이며, 현재 확보한 사본의 제공 사이트는 제조사 호스팅이 아니다. 판독과 BOM audit 후 기준 revision을 고정한다. 현대 SMD 버전·BD-2W·개조 클론과 동일한 회로라고 일괄 표기하지 않는다.

- 원본: [BOSS 서비스 노트 사본](https://stompboxelectronics.com/wp-content/uploads/2023/01/BOSS-BD2_ServiceNotes.pdf)
- PDF page 2: 부품표. page 3: 회로도. page 4: 출력 파형 검사. page 5: 정정표.
- 이미 확인한 정정: Q9·Q12는 초판의 2SA1335GR이 아닌 **2SA1049GR**로 기록해야 한다.
- GAIN은 250kA+250kA의 두 gang, TONE은 10kB, LEVEL은 100kA다.
- IC1은 **M5218AL**이다. 임의의 4558이나 이상 op-amp로 바꿔 stock이라고 표시하지 않는다.

클론 자료는 원본과의 차이를 확인하는 보조 자료다. 제거된 buffer·스위칭·다른 전원이나 부품 변경을 원본 회로로 가져오지 않는다.

## 3. 회로를 데이터로 옮기는 작업

| 단계 | 만들 자료 | 리뷰할 기준 |
| --- | --- | --- |
| 기준 고정 | source manifest: 문서·정정표·취득일·파일 hash·revision | 어느 회로를 기준으로 했는지 재현 가능 |
| 부품 대조 | BOM: 모든 refdes, 값, tolerance, 원 부품명, 모델 ID, pin 순서, source 위치, 확인 상태 | 회로도↔부품표↔정정표를 전부 대조. 흐린 표기는 미확인으로 남김. |
| 연결 대조 | node map 및 CircuitDocument | 단순 선 교차와 접속점을 구분. GND·전원·VR 보드·connector·jack 연결 포함. |
| 모델 대조 | 반도체 모델 registry 및 검증 데이터 | 같은 명칭이라도 rank와 pin 순서, 모델 출처를 확인 |
| 비교 기준 | 독립적으로 대조한 참조 netlist | 생성 코드가 만든 netlist를 다시 정답으로 삼지 않고 문서와 별도로 검토 |

기준 회로에서 포함할 영역:

| 영역 | 구현 내용 |
| --- | --- |
| 입력과 buffer | 입력 jack, coupling, bias·buffer 및 입력 임피던스 |
| 두 증폭단 | JFET·PNP 등 원래 discrete 구성과 feedback·두 GAIN gang·단 간 shaping |
| clipping과 tone | 원 다이오드·수동망·증폭기·TONE·LEVEL과 연결 순서 |
| 출력과 bypass | 출력 buffer와 부하, 전자식 switching·latch 및 제어 경로 |
| 전원·기준 전압 | 9V 공급에서 내부 8V·4V 계통을 만드는 원 회로와 decoupling |
| 제어·표시 | 풋스위치의 상태 전환과 LED 상태. 관련 회로와 전원 부하 포함. |

OFF도 페달 내부의 buffered bypass를 계산한다. ON 결과와 입력 원본을 crossfade하는 것만으로 실제 bypass를 대체하지 않는다. 물리 풋스위치의 기계적 bounce는 첫 testbench에서 이상 접점으로 정의하고, 전자 회로의 latch·JFET switching은 계산에 포함한다.

## 4. 부품 모델을 어떻게 확보하고 검증하나

| 부품 | 모델 방침 | 검증 항목 |
| --- | --- | --- |
| 저항·커패시터 | 기준 nominal 값에서 시작. tolerance, ESR·누설 등은 자료가 있을 때 별도 profile로 추가. | 값·단위·극성, RC 시간상수와 주파수 응답 |
| 다이오드·zener | 원 부품의 SPICE 모델 우선. 없으면 원 데이터·측정에 맞춰 파라미터화. | I–V, 역방향, junction capacitance와 동작 구간 |
| JFET | 원 부품·rank의 모델. differential pair와 switch 용도를 구분. | Idss, Vgs(off), transfer·output curve, capacitance·pin 순서 |
| BJT | 정정표까지 반영한 원 부품·rank 모델. | hFE, I–V, Vbe, junction capacitance, pin 순서 |
| M5218AL | 실제 부품의 자료·모델을 찾아 공급전압과 부하 조건에 맞춘 macromodel. | gain/bandwidth, slew, 출력 swing·전류 한계·바이어스 |
| 가변저항 | 실제 총 저항과 taper를 가진 물리 저항망. | gang 연동, wiper 방향, 회로 endpoint와 노브 방향 |

현재 각 반도체의 완전한 SPICE 모델과 실물 측정치는 확보하지 않았다. 모델이 없다고 다른 소자의 기본 모델로 조용히 교체하지 않는다. 같은 부품을 데이터시트로 모델링한 경우에도 출처, fit 구간·오차·미검증 구간을 기록한다. `제조사 모델`, `측정 기반 모델`, `데이터시트 기반 모델`, `미확보` 상태를 구분한다.

모델의 호환성과 배포 가능한 사용 조건도 도입 시 확인한다. 공급자가 암호화한 모델을 ngspice가 읽을 수 있다고 가정하지 않는다. 원 자료·모델 파일은 hash로 고정하고 어떤 build에서 사용했는지 기록한다.

## 5. 노브가 실제 회로를 바꾸는 방법

UI 값 0–10을 물리 회전 위치 `u=0…1`로 바꾼다. 회로의 VR refdes와 직접 연결된 binding을 사용한다.

- GAIN: 한 노브가 두 저항망의 wiper 위치를 함께 바꾼다. A taper의 실제 곡선은 potentiometer 자료나 측정으로 정하며, 임의의 dB 증폭 값으로 대체하지 않는다.
- TONE: B taper의 wiper를 변경한다. Web Audio high-shelf 파라미터를 대신 바꾸지 않는다.
- LEVEL: 원 회로의 A taper 가변저항을 변경한다. 이 조작으로 다음 회로에 보이는 임피던스도 함께 달라진다.

세 단자의 가변저항은 두 저항으로 전개한다. 사용된 rheostat 연결·wiper short는 원 회로대로 유지한다. taper·wiper 방향은 소리 변화와 회로도 양쪽에서 확인한다. 원 A taper의 중간 저항비를 찾기 전에는 `log`라는 이름만으로 임의의 곡선을 확정하지 않는다.

endpoint의 0Ω 때문에 수치적으로 작은 저항이 필요한 경우, 값과 오차 민감도 시험을 기록한다. 이 보정을 물리 부품값이나 확인된 측정치로 표시하지 않는다.

노브 그림, 수치 입력, 회로 파라미터는 같은 binding을 사용한다. 빠른 입력은 마지막 요청으로 합치고, 요청한 설정과 계산이 완료되어 재생 중인 설정을 별도로 추적한다.

## 6. 시뮬레이션에서 PCM까지

1. **회로와 조건 고정**: CircuitDocument, 모델·engine hash, 노브, bypass, 입력 파일, 전압 스케일, source/load impedance, 온도를 가진 job을 만든다.
2. **회로 생성 및 검사**: refdes·pin·net을 netlist로 전개하고 GND, 미확인 모델, 부유 node, pin 순서를 검사한다.
3. **동작점**: `.op`로 전원·bias를 계산하고 주요 노드 전압·전류를 저장한다. 실제 조건에서 불가능한 상태를 허용하지 않는다.
4. **선형 응답**: 작은 신호 `.ac` sweep으로 응답을 확인한다. 이 결과만으로 비선형 오버드라이브 소리를 생성하지 않는다.
5. **시간 계산**: 입력 WAV를 전압 source로 공급한다. 지원되는 WAV 입력 또는 PWL/callback 중 해당 native·WASM build에서 검증한 방식을 사용한다. 같은 전압 기준으로 데모와 테스트 신호를 넣는다.
6. **적응 시간 간격**: transient solver의 시간 step과 오디오 sample 간격은 다르다. 기본 검증은 48kHz 출력, 4× 내부 시간 격자를 후보로 하고, `Tmax`와 8×/더 작은 step 결과를 비교해 수렴·aliasing 오차를 측정한다.
7. **출력 추출**: 출력·선택 probe의 시간값을 받아 규칙적인 내부 sample로 보간하고, 검증된 저역 필터로 downsample한다. 보간만 하고 aliasing이 해결됐다고 처리하지 않는다.
8. **재생 분리**: 원시 전압·PCM을 보존한 뒤 청취용 전체 볼륨만 적용한다. limiter·정규화가 필요하면 별도 monitor 경로에서 적용하며 회로 검증값에는 적용하지 않는다.

capacitor 전하와 회로의 history를 오디오 chunk마다 초기화하지 않는다. 먼저 하나의 연속 transient 실행으로 전체 짧은 데모를 계산해 기준을 만든다. 시작 settling은 임의의 고정 길이만 자르지 않고 회로 상태가 안정되는지 검증한다. 전원 켜짐·switch transient를 관찰하는 시험에는 settling을 제거하지 않는다.

입력은 첫 reproducible testbench에서 `1 PCM full-scale = 1V peak` 등의 명시적 스케일을 사용하고 source 저항과 load를 고정한다. 이는 실제 기타 전체를 자동 재현했다는 의미가 아니다. 실물 비교에서는 재생·reamp·capture의 측정값으로 같은 조건을 만든다. 클립마다 loudness를 정규화해 gain 차이를 숨기지 않는다.

온도 기본 후보는 25℃다. 첫 단계는 nominal deterministic 파형이며, 부품 편차·PCB 기생·접점 bounce·transient noise까지 모두 재현됐다고 표시하지 않는다. 모델마다 검증 수준을 기록한다.

## 7. 브라우저 실행과 연속 재생

**첫 브라우저 모드:** Web Worker 안에서 ngspice/WASM으로 job을 계산하고, 결과 PCM을 Web Audio에 전달한다. Main thread에서 회로 방정식을 계산하지 않는다. job ID로 지난 결과를 버리고, 실행 중 취소가 어려운 build는 worker를 종료·재생성해 마지막 요청을 처리한다.

engine은 현재 확인한 공식 stable 47을 기준 후보로 하되 실제 빌드 호환 검증 후 고정한다. native와 WASM의 버전·build 옵션·모델·solver 설정을 일치시킨다. 기존 WASM 배포본에 필요한 JFET/BJT/model 기능이 빠져 있으면 직접 재현 가능한 build를 만들고 기록한다.

**후속 연속 모드:** Worker의 solver 결과를 queue/ring buffer에 넣고 AudioWorklet이 재생한다. 실제 callback의 sample 수와 sample rate로 deadline을 계산한다. 기본 128 frame/48kHz라면 약 2.67ms이며, Worklet은 그 안에서 읽기·재생만 하고 solver를 기다리지 않는다.

- 같은 transient 실행을 멈춰 파라미터를 바꾸고 이어가는 ngspice shared API를 먼저 확인한다. C API가 native에서 된다고 WASM의 threading·pause/resume도 된다고 가정하지 않는다.
- 파라미터 변경은 안전한 solver 경계에서 적용하고 원 회로 상태를 보존한다. topology 변경은 새 회로의 동작점·초기 상태를 계산하는 별도 절차다.
- shared memory를 선택하면 COOP/COEP, same-origin 자원, browser isolation, pthread build가 필요한지를 검증한다. 비공유 buffer 경로도 실제 성능을 측정한다.
- 동일한 전체 회로를 60초 이상 처리하면서 실시간보다 빠른 처리량과 여유, underrun·변경 지연을 측정한 환경에서만 연속 모드를 활성화한다.

연속 모드의 기준을 못 넘으면 계산 후 재생을 유지하고 성능 작업을 별도 plan으로 만든다. 최초 회로 검증 완료와 연속 실시간 완료를 하나의 상태로 묶지 않는다.

## 8. 정확도 검증 — 서로 다른 세 기준

| 기준 | 시험 | 완료 판단 |
| --- | --- | --- |
| 회로·부품 대조 | 원본·정정표↔BOM↔netlist, 소자 단위 I–V/RC | 모든 항목의 출처·확인 상태가 추적 가능. 미확인 핵심 항목은 stock 검증을 막음. |
| 계산 엔진 일치 | 같은 circuit·model·조건의 native↔WASM, step refinement | DC·AC·transient의 정해진 오차 기준을 통과 |
| 실제 페달 일치 | 같은 revision의 실물과 같은 전원·source·load·입력·노브 조건 | level·응답·왜곡·감쇠·bypass 비교와 residual·청취 결과 기록 |

첫 수치 오차 기준 제안: native↔WASM의 주요 DC 노드는 `max(1mV, |reference|×0.1%)`, AC는 유효 신호 구간에서 0.1dB·1°, transient는 기준 출력 RMS가 충분한 구간에서 상대 RMS 오차 0.1% 이하다. near-zero·deep notch는 별도 절대 오차로 평가한다. 더 작은 time step의 결과와 비교해 native 자체의 수치 오차도 측정한다. 이 값은 **실물 차이에 대한 보장값이 아니다**.

실행할 시험:

- 원본 부록의 200Hz·5mV p-p square 입력과 표시된 노브 위치로 TONE 최소·최대 파형을 대조한다. scan 그림은 파형의 형태·축을 확인하는 자료이며 샘플 단위 golden data로 간주하지 않는다.
- 작은 사인 입력의 20Hz–20kHz sweep, 입력 amplitude 변화, step·burst, 단음 decay와 독립 데모를 계산한다.
- GAIN/TONE 위치 5×5와 LEVEL 위치 3개의 조합, bypass ON/OFF에서 bias·응답·clipping과 decay를 확인한다.
- 시뮬레이션과 동일 입력을 실물에 넣어 출력만 capture한다. 입출력 지연·계측 gain을 보정하되 임의의 EQ·개별 loudness 정규화로 차이를 제거하지 않는다.
- 저왜곡 구간 주파수 응답과 gain, 비선형 구간 harmonic spectrum·THD·waveform residual·decay, bypass 특성을 각각 보고한다.

실물 비교의 정량 threshold는 계측 chain의 오차와 반복성·부품 편차를 먼저 측정한 다음 **비교 결과를 보기 전에** 후속 계측 plan으로 고정한다. 녹음된 앰프 소리와 페달 출력 자체를 직접 비교하지 않는다. 청취용 amp/cab을 쓸 경우 양쪽에 같은 monitor 경로를 적용한다.

실물 측정치를 아직 얻지 못했다면 `회로 계산 검증`과 `실물 음색 미검증`을 함께 적는다. 검증되지 않은 모델 상태를 실제 페달과 동일한 소리라고 홍보하지 않는다.
