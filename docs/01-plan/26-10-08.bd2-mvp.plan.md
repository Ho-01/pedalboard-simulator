## 1. 목표

실물 BOSS BD-2를 **작업 공간(Workspace)**에 자유롭게 배치하고, 실제 회로의 노브를 조절하면서 합성 기타 데모의 시뮬레이션 출력을 듣는다. 프레임, 페달, 패치 케이블은 별개 객체이며 [용어·데이터 구조](../04-architecture/domain-model.md)를 따른다.

**2026-10-08 사용자 리뷰 반영:** 이전 근사 오버드라이브 제안은 실제 회로 시뮬레이션으로 수정한다. 오디오는 선행 회로 plan의 CircuitDocument·부품 모델·ngspice 출력에서 얻는다. 회로 검증과 실물 음색 검증 상태를 화면·report에서 구분한다.

Pedal Playground의 배치 경험과 Solder의 조절하며 듣는 경험을 합치는 첫 단계다. 두 서비스 전체 기능을 한 번에 이식하지 않는다.

## 2. 사용자 동작

1. 그리드가 있는 작업 공간과 `BD-2 추가`, 데모 계산·재생 조작부가 보인다.
2. 추가하면 BD-2 한 개가 나타난다. 누른 채 드래그하면 원하는 위치로 움직인다. 그리드는 시각적 기준이며 자동 스냅은 하지 않는다.
3. 클릭하면 작업 공간 아래에 상세 영역을 펼친다. PC에서는 **좌측에 확대 실물 사진**, **우측에 수치 입력·슬라이더**를 둔다.
4. LEVEL·TONE·GAIN 값을 바꾸면 상세·작업 공간의 노브가 같은 각도로 바뀌고 실제 가변저항 값의 변경 job을 요청한다.
5. 상세의 풋스위치 또는 ON/OFF 조작으로 이펙트를 켜고 끈다. CHECK LED와 상태 표시도 함께 바뀐다.
6. `계산·재생`을 누르면 그 설정의 회로 출력이 계산된 뒤 반복된다. 노브를 바꾸면 재계산 상태와 현재 재생 설정을 표시한다. 결과가 준비되면 새 설정으로 전환한다. OFF는 같은 트랙의 실제 buffered bypass 계산 결과로 비교한다.
7. 입력·출력 파형을 접어서 볼 수 있게 하고 회로 revision과 계산 조건을 확인할 수 있게 한다. 내부 부품 편집·probe 선택 UI는 후속 plan으로 확장한다.

모바일에서는 작업 공간, 확대 사진, 조절값을 세로로 배치한다. 데모 조작부는 쉽게 접근할 수 있게 유지한다. 페달의 일반 클릭은 선택만 하며 ON/OFF를 바꾸지 않는다. 처음에는 계산 후 청취 모드이며, 매 순간 연속 실시간 계산은 별도 성능 plan 대상이다.

## 4. 수치와 시각화

| 조작부 | UI 값 | 동작 |
| --- | --- | --- |
| LEVEL | 0–10, 0.1 단위, 초기 5 | 물리 LEVEL 가변저항의 위치를 변경. endpoint·누설도 회로 결과로 계산. |
| TONE | 0–10, 0.1 단위, 초기 5 | 물리 TONE 가변저항의 위치를 변경. 실제 수동망의 밝기 변화 계산. |
| GAIN | 0–10, 0.1 단위, 초기 5 | 두 gang의 위치를 함께 변경. 원 discrete 증폭단의 gain·clipping 계산. |
| 풋스위치 | ON/OFF, 초기 OFF | 전자식 switch·latch의 상태를 변경하고 CHECK 표시를 동기화. |
| 전체 볼륨 | 0–100%, 초기 20% | 데모 조작부에 배치하며 페달 ON/OFF와 무관하게 적용. |

0–10은 앱이 정한 상대값이다. 실제 BD-2에 숫자 눈금이 있는 것으로 표현하지 않는다. 노브는 최저 약 7시 → 중앙 12시 → 최고 약 5시로 회전하며, 각도는 동일한 값에서 계산한다.

사진의 원본 노브 영역을 CSS 원형 마스크·배경으로 분리해 회전시키는 방식을 우선 사용한다. 실제 사진 위에 임의의 그림 노브를 얹어 두 개의 지시선이 남는 방식은 사용하지 않는다. 풋스위치는 누르는 동작과 LED 상태를 표현하며 실제 없는 토글 스위치를 추가하지 않는다.

## 5. 코드와 상태

| 위치 제안 | 책임 |
| --- | --- |
| `src/features/workspace/` | 작업 공간, 선택, 드래그, 화면 위치 제한 |
| `src/features/pedals/bd2/` | BD-2의 화면 정의, 실물 사진, 노브·LED 좌표 |
| `src/features/inspector/` | 확대 보기와 수치 입력 |
| `src/features/player/` | 데모 재생 및 전체 볼륨 |
| `src/circuits/`, `src/simulation/` | 선행 plan의 회로·binding·solver·검증 데이터 재사용 |
| `src/audio/playback/` | 계산된 PCM의 재생 위치와 monitor 볼륨 관리 |
| `public/pedals/boss-bd2/` | 실제 페달 사진 |
| `public/audio/` | 직접 생성한 클린 데모 트랙 |

페달의 배치·선택과 회로 설정을 분리해 관리한다. 화면은 요청된 설정에서 노브를 그리고, 엔진은 같은 control binding으로 물리 회로를 갱신한다. `requestedSettings`, `appliedSettings`, `renderJobId`로 계산 지연과 지난 job을 구분한다. 이동한 위치가 소리의 순서를 바꾸지 않는다. 이번에는 페달 한 개를 고정 testbench에 연결한다.

화면 픽셀과 별개인 작업 공간 좌표를 사용한다. 첫 표시 영역은 600×350mm를 제안하며 실제 프레임을 뜻하지 않는다. 페달 사진의 치수 metadata는 선택한 외형 기준으로 기록하고 회로 revision과 분리한다. 사진 여백·잭 돌출을 보정하고 비율을 찌그러뜨리지 않는다. 새로고침 저장은 이번 필수 범위에 넣지 않는다.

## 6. 오디오 설계

합성 클린 데모 → 전압 입력 testbench → 실제 BD-2 회로 계산 → 출력 전압의 sample 변환 → PCM → 별도 monitor 볼륨 → 스피커로 연결한다. 구체적인 모델·동작점·시간 계산·aliasing·검증은 [회로 plan](26-10-08.bd2-circuit-simulation.plan.md)을 따른다.

원본 트랙은 8초 안팎의 독립 리프를 현의 감쇠를 흉내 내는 합성 방식으로 생성한다. 생성 코드·고정 seed·PCM↔전압 스케일을 기록한다. 합성 기타 자체의 정확도와 BD-2 회로 정확도는 별개의 문제다.

노브 변화는 150–300ms 후보의 debounce로 마지막 설정을 계산한다. 이 시간은 계산 완료 지연에 대한 약속이 아니다. 재계산 중에는 요청한 설정을 표시하고 이전 재생 설정을 명시한다. 완료된 새 buffer는 짧은 전환으로 이어 재생하되 이 전환 처리를 원 회로의 switch transient와 혼동하지 않는다.

Workspace가 비어 있으면 장치 없는 testbench의 입력을 청취할 수 있다. 페달 OFF는 실제 bypass 회로의 결과이며, 페달 삭제와 다르다. 일시정지는 위치를 유지하고 처음부터 재생은 0초에서 시작한다. `AudioBufferSourceNode`는 한 번에 하나만 활성화한다. 사용자 조작으로 AudioContext를 시작하고 계산·재생 실패를 표시한다.

입출력 파형은 monitor 정규화·limiter 이전 값을 사용한다. waveform의 volts/time 축과 계산 조건을 표시하고 회로 검증·실물 검증 상태를 구분한다. 앰프·캐비닛·외부 입력·연속 실시간·내부 회로 편집 UI는 후속 plan 대상이다.

## 7. 구현 순서와 검증

1. 실물 사진과 단일 페달 배치·선택을 만든다. 위치 제한과 클릭/드래그 구분을 확인한다.
2. 수치 조절과 사진의 노브·LED를 연동한다. 끝값, 잘못된 숫자, 터치 입력을 확인한다.
3. 데모 트랙과 재생 컨트롤을 만든다. pause·restart·loop와 중복 재생 방지를 확인한다.
4. 검증된 회로 engine과 ON/OFF·노브·파형을 연결한다. 지난 job·연속 입력·실패·삭제·재추가 때 다른 회로 출력이 재생되지 않는지 확인한다.
5. 타입 검사·빌드와 필요한 좌표·binding·job 상태 테스트를 수행한다. 같은 회로 job을 직접 계산한 결과와 UI 재생 buffer·파형을 비교하고, 내부 bypass·노브·부하 조건이 일치하는지 확인한다.
6. 390×844, 768×1024, 1366×768, 1920×1080 화면과 가로 모바일을 검사한다. Chrome/Edge를 우선 검증하고 가능한 Safari/iOS 검증 여부를 report에 명시한다.
7. 사용자가 같은 데모로 Gain·Tone·Level·ON/OFF 차이를 청취할 수 있게 배포한다. 자동 수치 검증과 실제 청취 확인을 구분한다.

## 8. 제외 및 후속 plan

실제 회로 계산은 필수 선행 범위다. 프레임 배치 UI, 여러 페달과 케이블·전체 회로 조립, 저장·공유·로그인, 실물 기타 입력, 직접 파일 업로드, 모바일 고급 패닝, 내부 회로 편집 UI와 연속 실시간은 순차 후속 plan으로 구현한다. 데이터 구조는 이러한 확장을 막지 않도록 처음부터 분리한다.
