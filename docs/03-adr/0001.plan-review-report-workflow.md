# ADR-0001: plan → 사용자 리뷰 → 구현 → report

- 상태: 채택
- 결정일: 2026-10-08
- 근거: 사용자가 이번 프로젝트의 개발 절차로 명시했다.

## 배경

초보 단계부터 구현 과정을 직접 검토하고, 설계와 실제 구현의 차이를 추적하고 싶다.

## 결정

기능 개발 전에 `docs/01-plan/<YY-MM-DD>.<feature>.plan.md`를 작성하고 사용자의 리뷰 및 승인을 받는다. 구현 완료 뒤 대응 report를 `docs/02-report/`에 작성한다.

report는 계획과 일치한 항목을 ID 목록으로 생략하고, 다르게 구현하거나 추가한 내용만 이유와 함께 상세히 적는다. 통합 검증·FE 의존 작업·후속 plan 등 미수행 항목을 명시한다.

## 결과

문서가 실제 개발의 기준이 된다. plan 검토 요청과 승인 완료를 구분하고, 승인 전에 코드를 구현하지 않는다. 관련 절차는 [개발 가이드](../00-guide/development-workflow.md)에 정리한다.
