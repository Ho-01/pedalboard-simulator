# ADR-0002: 실제 회로 계산과 브라우저 실행·정적 배포

- 상태: 제안 — 사용자 승인 전
- 작성·수정일: 2026-10-08
- 관련 plan: [기반](../01-plan/26-10-08.repository-and-deployment.plan.md), [회로](../01-plan/26-10-08.bd2-circuit-simulation.plan.md), [화면](../01-plan/26-10-08.bd2-mvp.plan.md)

## 배경과 사용자 요구

실물 페달의 회로 구성과 최대한 동일하게 계산해 소리를 재현하고, 이후 부품·배선을 직접 수정해 파형을 확인한다. 이전 근사 오버드라이브 초안은 승인되지 않았으며 사용자 리뷰에 따라 수정한다.

## 제안

- 검증 기준 엔진은 native ngspice, 브라우저 엔진은 같은 버전·모델을 포함한 ngspice/WASM으로 구성한다.
- 저항·커패시터·반도체·가변저항·전원·스위치의 연결을 CircuitDocument에서 netlist로 변환한다.
- React는 배치와 편집 화면을 담당한다. Worker는 회로 계산, Web Audio는 계산된 PCM의 재생을 담당한다.
- 우선 정해진 조건의 회로 파형을 계산하고 재생한다. 연속 실시간 재생은 상태 보존·성능 검증 후 단계적으로 구현한다.
- 운영 Nginx는 앱과 WASM·모델 자원을 제공한다. 부하가 큰 native 참조·컴파일 작업은 운영 서비스와 분리한다.

## 대안과 이유

일반적인 WaveShaper·EQ 조합이나 측정 음색·학습 입출력 모델만으로는 사용자가 수정한 회로의 노드 전압·전류를 설명할 수 없다. 이번 회로 solver의 대체 방법으로 선택하지 않는다.

처음부터 자체 nonlinear MNA solver를 작성하면 수치 수렴과 반도체 모델 검증 범위가 커진다. 먼저 ngspice를 사용하고, 필요하면 동일 회로·오차 기준을 통과하는 실시간 solver를 후속 plan에서 검토한다.

## 결과

회로의 부품 모델 정확도, native↔WASM 일치, 실물 측정 일치, 연속 재생 성능을 각각 검증해야 한다. 실시간 처리량이 부족하면 동일 solver의 계산 후 재생 모드를 유지한다. 처리 속도를 이유로 임의의 왜곡 함수로 대체하지 않는다.

후속 실시간 구성에서 shared memory를 사용하면 이 사이트의 COOP/COEP·정적 자원 정책도 별도로 검증한다. 승인 후 상태와 실제 선택 버전을 갱신한다.
